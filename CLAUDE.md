# Portfolio site (Adil Pervez)

An Astro site styled as a cel-shaded comic page (Borderlands-like): the first screen shows name, role and four results, then project cards. Every claim has a receipt (a file at a pinned commit) and failures are published on purpose. Overview in `README.md`; the procedure for new work is in `ADD_PROJECT.md`.

## Commands

Load nvm first on this machine (system Node is v12): `export NVM_DIR=/mnt/data/.nvm; . $NVM_DIR/nvm.sh`.

```bash
npm run dev            # eval the search box, then http://localhost:4321
npm run check          # schema + content rules + every receipt against the pinned GitHub file
npm test               # vitest
npm run check:types    # astro check
npm run build          # eval + build + share cards (about 30 s)
npm run new-project -- <slug> --repo Owner/name [--tier archive]
npm run drift          # which pinned repos have moved on
```

## When asked to add or change a project

Use the `add-portfolio-project` skill (`.claude/skills/add-portfolio-project/SKILL.md`) or follow `ADD_PROJECT.md`. In short: scaffold with `new-project`, read the repo, cite real numbers, run `check`/`test`/`check:types`, look at it in the browser, then stop and ask before publishing.

## Rules that must not be broken

- **Never invent or estimate a number.** Every metric, assertion, failure and chart needs a `receipt` whose `find` text is copied verbatim from the file at the pinned commit. If it is not in the repo, ask the user for it or leave the claim out.
- **Plain voice.** Short, specific, first-person copy about what was done and what happened. No hype, no em dashes, no "X, not Y" flourishes.
- **Keep the look.** Style lives in `src/styles/global.css` tokens: thick ink outlines, flat colour with a hard highlight band, halftone dots, hard offset shadows, comic type. Do not bring back gradients, glows, glass cards, terminal styling or bright yellow; the palette is dark and muted on purpose (teal accent; no orange, no yellow). Outlines use `--line` and text uses `--ink` (they differ in dark mode). Text on a fill uses `--on-fill` (cream) and every fill must keep it at 4.5:1 or better in both themes; use `--hl`/`--on-hl` for soft highlights.
- **Failures stay in.** A project needs at least one `fail` or `inconclusive` assertion and two failures. Do not soften a weakness the repo states, and do not add one the repo does not support.
- **No em dashes in copy** (the check enforces it) and no `TODO` left in a content file.
- **Do not edit `search-eval.json` by hand.** It is generated by `scripts/eval-search.ts`. Do not add questions to the `test` split of `src/data/search-gold.json` after seeing results; add to `dev`.
- **Do not commit, push or deploy unless asked.** When committing: plain messages, no `Co-Authored-By` or other AI attribution trailers (the user has asked for this explicitly), and use the repo-local identity `Adilmp <adilmp@users.noreply.github.com>` (the global git identity on this machine belongs to another account).
- Keep the user's private repos and student/user data out of the site. Private repos get no receipts.
- Open VS Code on this folder (`code -n /mnt/data/portfolio`) when starting work, so the user can watch the code change.

## Layout

- `src/content/projects/*.md`: one file per project (schema in `src/lib/schema.ts`)
- `src/lib/`: schema, BM25 search, diagram router and validator, chart renderer, share-card renderer
- `src/components/`, `src/pages/`, `src/styles/global.css`: the UI
- `scripts/`: `check`, `eval-search`, `new-project`, `drift`, `check-links`
- `tests/`: vitest
- `src/data/site.ts` holds the name, pitch, about text, experience/education/skills (copied from the CV, keep in step), the four `heroResults` (project + headline tile) and photo/email/LinkedIn/CV; the photo is `public/img/adil.jpg`

## Things worth knowing

- Diagram text is measured at build time; labels over 21 characters or subtitles over 30 fail `check`.
- `find` strings must not span a line break in the source file.
- Each flagship needs a `role` line; it is shown on the card and the page header.
- The CV behind the download button is the user's own PDF, `public/adil-pervez-cv.pdf` (a copy of `/mnt/data/Documents/Resumes/Adil_Pervez_CV_AI_Engineer.pdf`). Do not edit or regenerate it; if its numbers disagree with the site, tell the user. Cards show a mini version of the project's first chart (so order `charts` with the strongest first), title, tagline, role and two buttons only; stack tags and the verdict bar live on the case-study page.
- `npm run build` takes about 30 s because share cards are rendered with satori + resvg.
